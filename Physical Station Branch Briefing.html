1. Why this branch exists

  • Players should be able to build rooms and controllers before airlocks without accidentally creating unrelated Station identities.
  • A Station must keep its identity when its main controller is replaced by an eligible surviving controller.
  • Breaking a construction connection must disable the detached fragment's Station services without deleting its membership.
  • One physical room must not acquire duplicate atmosphere, volume or operating costs because it contains multiple controllers.
  • The player needs a direct way to choose which surviving fragment becomes active.
  • This branch implements physical Station behavior. It does not implement Station merging, named transport routing or new Automated Facility gameplay.

3. Lifecycle walkthroughs

These short ordered walkthroughs replace interactive diagrams so the briefing remains self-contained and readable offline.

Building and joining

  1. A Station construction block is placed.
  2. The Station checks neighboring membership and claims connected unassigned construction when one identity applies.
  3. A controller forms, adopts or establishes membership, and supplies its room observations.
  4. The Station rebuilds the loaded service graph for the active fragment and computes shared rooms and operating demand.

Breaking and recovering

  1. Block removal updates recorded connectivity.
  2. A detached fragment keeps membership but loses service access. Station Plugs no longer draw Station energy.
  3. If the main controller was destroyed, an eligible successor is chosen from the previously active fragment.
  4. If no eligible successor exists, a player opens a surviving controller and clicks Make Master. The server checks team ownership and switches the active fragment.

Environment and saves

  1. Structure checks replace controller observations. Room identity, shell and volume come from the geometry owner.
  2. The Station combines observations, updates sealing when dirty and advances shared oxygen during ticking.
  3. Player hazards query the actual active room interior, including rooms beyond the main controller.
  4. Asset persistence saves construction and room oxygen. Loaded controls rebuild service references without becoming a second persistent owner.

5. Reviewer focus

  • Confirm the distinction between Station identity, active construction fragment and physical room.
  • Inspect removal eligibility before connectivity changes and the absence of succession on unload.
  • Check room observation freshness, shared device accounting and airlock behavior with several controllers in one room.
  • Inspect the server-side team check on Make Master and the asset-format cut.
  • Profile representative large builds before claiming scalability. Construction lookup, topology traversal and full room rescans remain real costs.

6. What this does not add

  • No command or UI for merging two existing Station identities.
  • No Station-local named Rocket endpoint scheduler or bulk route replacement.
  • No commands that stop independent GregTech machines. Only Station-provided services are withdrawn.
  • No legacy save migration, per-block Tile Entity membership store or second global identity registry.
